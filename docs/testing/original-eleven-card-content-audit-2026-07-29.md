# 原版 11 张章节卡与七图发布边界核验

日期：2026-07-29

## 结论

原版章节页确实预留了 11 张卡片，但原版 APK 并不包含 11 个完整可玩关卡。可确认的
发布边界是：

- 11 张规划卡片；
- 3 张带完整故事正文和开场顺序的卡片；
- 7 张带可加载 prefab 的可玩地图；
- 8 张没有正文、角色、字幕、动画和播放顺序的后续占位；
- 4 份有事件配置、但没有地图 prefab 的编辑草稿。

因此当前维护版的三章七图没有漏删原版已发布关卡。把后续占位直接开放会复现原版黑屏，
凭空补写剧情、美术和任务又会把非原作内容冒充历史恢复。本项目选择保留规划资料、关闭
无效入口，并完整测试全部七张真实地图。

## APK 资源核验

原版资源索引与当前恢复工程中都只能找到以下七个地图 prefab：

| 章节 | 地图资源 |
|---|---|
| 第一章 | `scenes_d1_1`、`scenes_d1_2` |
| 第二章 | `scenes_d2_1`、`scenes_d2_2` |
| 第三章 | `scenes_d3_1`、`scenes_d3_2`、`scenes_d3_3` |

配置文件另有 `scenes_d1_3`、`scenes_d2_3`、`scenes_d3_4`、`scenes_d3_5` 四行
编辑草稿，以及 `scenes_d4_1` 和 `111111` 两行编辑器遗留数据。它们都没有对应 prefab，
也不在 APK 的可加载资源路径中。

## 原版模拟器黑盒验证

测试在原版应用的独立包名下进行，不覆盖维护版：

1. 写入原版独立存档键，解锁章节卡；
2. 打开章节页，确认第 1–4 张卡的原版名称和锁定状态；
3. 选择“团结”，确认原版故事正文和“进入关卡”按钮存在；
4. 确认加载后，日志进入章节与地图初始化并完成过场场景切换；
5. 最终画面持续全黑，无法移动、交互或继续。

这个结果与静态资源索引相互印证：章节卡和故事数据存在，不代表对应地图已经随 APK
发布。后续八张空卡比该入口更不完整，不具备可执行的通关条件。

## 维护版防回归

`original-content-boundary.json` 保存 11 张规划卡、已发布故事卡、未发布占位和编辑草稿
的机器可读边界。发布内容门禁会同时检查：

1. 11 张卡片的编号和标题没有在恢复过程中丢失；
2. 前三张仍有正文和开场顺序；
3. 第 4–11 张仍是原版空占位，没有被伪造内容污染；
4. 地图目录恰好包含发布清单中的七个 prefab；
5. 缺 prefab 的草稿和编辑器测试行不能进入发布清单；
6. 七图的门、收藏、史实、答题和存档边界继续通过。

本轮从 Creator 源工程重新生成 Android Debug APK 后，按发布清单完成 8 次轮巡，覆盖七图
并回绕首图。每张地图都执行冷加载、道路触控、切后台、回前台、焦点检查和内存采样；
日志没有 JavaScript 异常、Native 崩溃、ANR 或资源加载失败。轮巡同时发现并移除了
Creator 2.4.15 对旧 `cc.eventManager` 入口记录的兼容错误，新构建复测不再出现该日志。

若未来取得作者提供的后续完整工程，应同时补齐地图 prefab、依赖美术、章节剧情、任务
闭环、入口出口和通关测试，再显式更新这份边界；仅补一行配置不算恢复完成。
